# Архитектура

`finance.Main` связывает CLI с прикладной логикой и файловыми адаптерами. `finance.core` использует Java SE и свои интерфейсы. Инфраструктура реализует эти интерфейсы, CLI получает их через конструктор.

| Модуль | Обязанности |
| --- | --- |
| `finance.core.Wallet`, `Transaction`, `Rules` | Неизменяемый снимок, типы операций, нормализация и валидация. Категория операции и бюджета должна существовать. Переименование переносит связанные записи. |
| `finance.core.Reports`, `Alerts` | Расчёты на `BigDecimal`, включительные периоды, накопительные бюджеты и сообщения о порогах. |
| `finance.core.Accounts` | Регистрация и проверка пароля через `AccountRepository`. Для аккаунтов генерируются отдельные соли. Хеширование — PBKDF2-HMAC-SHA256, 600 000 итераций. |
| `finance.core.WalletRepository`, `AccountRepository`, `SnapshotStore` | Контракты хранения кошельков, учётных записей и снимков. |
| `finance.infra.FileAccounts`, `FileWallets` | Файлы `accounts/<login>.account` и `wallets/<login>.csv` в каталоге данных. Запись через временный файл рядом с целевым и атомарное перемещение. |
| `finance.infra.CsvSnapshots`, `DirectoryLock` | Чтение и запись согласованных CSV-снимков и блокировка каталога. |
| `finance.cli.FinanceCli`, `Terminal`, `ReportView` | Обработка команд и сеанса, сообщения об ошибках, ввод пароля, печать сводок. |
| `finance.Main` | Разбирает аргументы, связывает модули и держит блокировку на время работы. |

## Поток изменения кошелька

1. CLI проверяет команду и активный сеанс.
2. Core формирует новый снимок с учётом правил модели.
3. Хранилище записывает снимок в файл конкретного пользователя.
4. При успешной записи CLI подменяет снимок в памяти и выводит результат. При ошибке остаётся прежний снимок. Ошибка финальной записи в конце потока возвращает код 1.

При входе сначала проверяется пароль, затем загружается кошелёк. Отсутствующий файл означает пустой кошелёк нового аккаунта. Повреждённый файл приводит к ошибке входа и сохраняется для восстановления.

## Формат CSV v1

UTF-8, четыре поля в строке. Первая строка содержит версию, вторая — заголовки. Имя категории не содержит запятых, кавычек и переводов строки.

```csv
finance-wallet,1,,
type,category,amount,date
CATEGORY,еда,,
BUDGET,еда,1000.00,
EXPENSE,еда,125.50,2026-11-22
```

Строки `CATEGORY` и `BUDGET` уникальны для каждого имени. `INCOME` и `EXPENSE` описывают операции в порядке добавления. Импорт проверяет весь снимок до сохранения. Экспорт создаёт новый файл с категориями, бюджетами и операциями. Файлы аккаунтов содержат соль и хеш пароля и хранятся отдельно от снимка. Финансовые файлы читаемы пользователем ОС, их нужно хранить отдельно от репозитория.

## Границы локальной версии

Один активный сеанс на процесс и один процесс на каталог. Файловая система каталога данных должна поддерживать блокировки и атомарное перемещение. Операции хранятся в памяти и записываются целым снимком. Бюджеты накопительные, периоды доступны в отчётах.
